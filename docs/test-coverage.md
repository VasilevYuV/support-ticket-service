# Покрытие Java/Kotlin и результаты тестирования

**Автор:** Васильев Юрий, 4П1.23

## 1. Объём и воспроизведение

BL-19 подтверждает покрытие бизнес-логики обоих языков и сводит результаты UT, IT, E2E и исправлений дефектов. Исходники приложения и тестов на этом этапе не изменялись. В Gradle подключён JaCoCo 0.8.14, версия закреплена в gradle/libs.versions.toml, зависимости jacocoAgent и jacocoAnt записаны в gradle.lockfile.

Нужны JDK 25, корректный JAVA_HOME и работающий Docker. Из корня проекта:

```powershell
.\gradlew.bat spotlessCheck check --no-daemon --console=plain
```

`check` и `build` включают `jacocoTestReport`, который зависит от полного `test`. Для отдельного отчёта:

```powershell
.\gradlew.bat jacocoTestReport --no-daemon --console=plain
```

Gradle может использовать актуальные результаты предыдущего запуска. Для принудительного повторения всех тестов и пересборки отчёта добавляется `--rerun-tasks`. После выборочного `test --tests ...` для итогового покрытия нужен полный повторный запуск без фильтра. Отчёт использует только `build/jacoco/test.exec`, результаты отдельных unitTest, integrationTest, e2eTest и reportRegressionTest к нему не прибавляются.

| Артефакт | Путь |
|---|---|
| Покрытие HTML с переходом к строкам Java и Kotlin | build/reports/jacoco/test/html/index.html |
| Покрытие XML | build/reports/jacoco/test/jacocoTestReport.xml |
| Данные выполнения JaCoCo | build/jacoco/test.exec |
| Результаты тестов HTML | build/reports/tests/test/index.html |
| Результаты каждого теста и параметра XML | build/test-results/test/TEST-*.xml |
| Журнал первого запуска BL-19 | build/bl19-check.log |
| Журнал сборки с закреплёнными зависимостями | build/bl19-build.log |

Артефакты находятся в игнорируемом каталоге build и удаляются командой clean. Для сдачи или CI их нужно сохранить отдельно. На [BL-24](continuous-integration.md) подготовлена загрузка отчётов через pipeline; фактическая загрузка на GitHub ожидает запуска на PR.

## 2. Фактический запуск

Проверено 11.11.2026 на Windows, JDK 25, Gradle 9.7.0, Kotlin 2.4.21, JaCoCo 0.8.14 и PostgreSQL 18.6 через Testcontainers. Ветка feature-c/test-coverage, базовый коммит d68efdb86d2435086d597ecceafbf6bbeca2a039 (BL-18), поверх него незакоммиченные изменения сборки BL-19. Этот SHA обозначает исходную версию приложения и тестов, а не ещё не созданный коммит этапа.

Первый запуск: `spotlessCheck check --write-locks --no-daemon --console=plain`, завершён успешно. `--write-locks` использован для первоначального закрепления зависимостей JaCoCo; при обычной проверке он не нужен. Полный test выполнен заново с подключённым агентом JaCoCo. В JUnit XML: **505 выполнений, 0 падений, 0 ошибок, 0 пропусков**.

Повторная команда `spotlessCheck build --no-daemon --console=plain` без обновления lock-файла также успешна: собран исполняемый JAR, полный test повторно выполнен, вновь получены 505 успешных выполнений и те же метрики покрытия. Эти два прогона не складываются в число уникальных проверок.

Модульный набор содержит 53 метода в 11 классах, интеграционный 79 методов в 10 классах; подробная связь с требованиями сохранена в [модульных проверках](unit-testing.md), [интеграционных проверках](integration-testing.md) и [сквозных сценариях](end-to-end-testing.md).

## 3. Метрики покрытия

Измеряется весь основной source set main, включая контроллеры, сервисы, собственные репозитории, валидацию, DTO, сущности и конфигурацию. Пользовательских исключений классов нет. Применяются стандартные фильтры сгенерированного байткода JaCoCo. Интерфейсы без исполняемого кода не дают строк или ветвей. Покрытие библиотек Spring/Hibernate, SQL и тестового кода в эти числа не входит.

Данные взяты из XML: для языков суммируются counter у sourcefile по расширению .java/.kt, для общего итога используется корневой counter. Строки вложенных классов повторно не суммируются. Процент равен covered / (covered + missed), округление до двух знаков. Branch означает ветвь байткода JaCoCo, а не отдельное требование или сценарий.

## 4. Непокрытые участки

Ни один участок не скрыт из отчёта. Ниже перечислены все исходники с непокрытыми инструкциями или ветвями.

| Исходник и строки | Наблюдение и ограничение проверки |
|---|---|
| SupportApplication.java:9-10 | Метод main не вызывается тестами: Spring поднимается через тестовый контекст. Проверка исполняемого JAR и Docker остаётся отдельной проверкой запуска, её покрытие не включено. |
| QueryParameterInterceptor.java:15,22-23 | Не выполнены обход для обработчика, не являющегося HandlerMethod, резервное чтение annotation.value при пустом name и вывод имени параметра без имени в аннотации. Текущие контроллеры задают name; Spring также согласует псевдонимы name/value при чтении аннотации в HandlerMethod. Проверки неизвестных, пустых и повторных параметров проходят. |
| StrictJsonObject.java:35,55 | Не покрыты ветвь старшего суррогата, после которого идёт не младший суррогат, и явный JSON null числового узла (отсутствие categoryId проверено отдельно). Это пробелы покрытия общего JSON-помощника; проверка Java null в TicketRequestValidator не заменяет проверку соответствующего HTTP-тела. Имеющиеся проверки Unicode не доказывают все возможные последовательности. |
| ApiExceptionHandler.java:51-52,65-75,87-102 | Не выполнены извлечение ApiException из HttpMessageNotReadableException, обе формы TypeMismatchException, 404 и default в двух switch общего обработчика Spring. Текущие параметры разбираются явными парсерами, бизнес-404 проходит через handleApiException. Общий неожиданный сбой и HTTP-ошибки 400/405/406/415 проверены по другим путям. |

Таким образом, непокрытых ветвей правил статуса и времени в данном отчёте нет. Перечисленные пробелы относятся к другим путям обработки и сохраняются как ограничения, а не как доказанные дефекты. Расширение вариантов общего JSON-помощника и обработчика ошибок возможно отдельно, если потребуется проверить эти пути.

## 5. Дефекты и статус требований

В [журнале дефектов](defects.md) сохранены два фактически найденных и исправленных дефекта: DEF-01 (сокращённый UUID, исправление 9bd3573) и DEF-02 (старые календарные даты PostgreSQL, исправление ba2deb0). На BL-18 их исходные проявления воспроизведены в изолированной копии, после восстановления исправлений успешны все 10 выбранных выполнений. На BL-19 те же регрессионные методы входят в успешные 505 выполнений; вариант без исправления повторно не запускался. Свидетельства до и после исправления находятся в [отчёте BL-18](defect-regression.md).

RV-03 подтверждён в части автоматических тестов приложения, покрытия Java/Kotlin и журнала дефектов. Новых дефектов в этом прогоне не выявлено. UT-01-UT-15, IT-01-IT-15 и E2E-01/E2E-02 успешны в описанном тест-планом объёме. Полная практика ещё не завершена: OPS-01-OPS-10, фактическая доставка/откат, окончательная проверка материалов и защита остаются последующими этапами. Результат JaCoCo не подтверждает публикацию, развёртывание или резервное восстановление.
