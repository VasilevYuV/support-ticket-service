# Журнал дефектов

**Автор:** Васильев Юрий, 4П1.23

Здесь фиксируются фактически воспроизведённые ошибки. Плановые задачи и искусственные сбои для проверки rollback не считаются найденными дефектами.

## DEF-01. Сокращённый UUID принимается как корректный

| Поле | Значение |
|---|---|
| Обнаружен | 11.11.2026 при проверке BL-08, ветка `feature-c/request-validation` на основе `4974af8` |
| Требование | Контракт UUID и IT-04: неверный формат даёт `400` до поиска заявки |
| Серьёзность | Средняя: нарушение входного контракта и неверный HTTP-статус |
| Статус | Исправлен в коммите `9bd3573` (BL-08), регрессия пройдена |

Шаги воспроизведения: запустить приложение с PostgreSQL и выполнить `GET /api/tickets/1-1-1-1-1`. Ожидается `400 INVALID_REQUEST`, нарушение поля `id`. При первом прогоне BL-08 получен `404`: сокращённая запись была преобразована в UUID и передана на поиск. Из 193 выполнений тестов это было единственное падение.

Проверка через преобразование аргумента Spring MVC не обеспечила строгий текстовый формат. Исправление: контроллер принимает исходную строку, явно вызывает `ApiUuid.parse` с проверкой групп `8-4-4-4-12` и только затем передаёт UUID сервису. Корректный UUID с прописными буквами по-прежнему допускается.

Регрессия: `RequestValidationApiTest.rejectsNonCanonicalUuid`, вариант `1-1-1-1-1`. Дополнительно проверены UUID без дефисов, в скобках и с неверными символами. После исправления все 193 выполнения тестов прошли. Текущее XML-свидетельство: `build/test-results/test/TEST-ru.vasilev.support.ticket.controller.RequestValidationApiTest.xml`; оно пересоздаётся при запуске тестов.
