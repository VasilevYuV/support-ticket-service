# Проверка исправлений реальных дефектов

**Автор:** Васильев Юрий, 4П1.23

## 1. Объём BL-18

Проверены DEF-01 и DEF-02 из [журнала дефектов](defects.md). Они фактически обнаружены и исправлены на BL-08 и BL-14. BL-18 подтверждает, что существующие регрессионные тесты выявляют эти ошибки при отключённом исправлении и проходят после его восстановления. Новые дефекты не добавляются для выполнения формального минимума.

Для воспроизводимости добавлен scripts/verify-regressions.ps1. Он использует тесты проекта и не меняет бизнес-код, API, схему или зависимости. Проверка отсутствия запрещённых тире расширена на каталог scripts.

## 2. Запуск

Нужны PowerShell 7, Git, JDK 25, настроенный JAVA_HOME и работающий Docker. Из корня проекта:

```powershell
.\scripts\verify-regressions.ps1
```

Проверяется именно текущий коммит HEAD. Незакоммиченные изменения исходников не попадают в копию. Скрипт фиксирует полный SHA, создаёт ZIP через git archive и распаковывает его в новый каталог build/regression-<id>/project. Ни git checkout, ни изменение рабочей копии исходников не выполняются.

Для каждого дефекта выполняются две проверки в изолированной копии:

1. Отключить конкретное исправление и запустить выбранные методы тестов.
2. Проверить новый JUnit XML, ожидаемое количество выполнений и конкретное проявление исходной ошибки.
3. Восстановить исходные байты файла в finally, в том числе при ошибке проверки.
4. Повторить те же методы с исправлением и потребовать успешный результат без пропусков.

Обычный ненулевой код Gradle не считается доказательством воспроизведения дефекта. Проверяются свежесть XML, число тестов, отсутствие пропусков и XML-ошибок, а также ожидаемая пара значений в сообщении падения. Ошибка сборки без нового JUnit-свидетельства не засчитывается как воспроизведение дефекта. Для каждого запуска используется --rerun-tasks, чтобы результат не брался из кеша.

Это проверка текущего коммита с исправлением и без него, а не запуск старого коммита целиком. Варианты без исправлений воспроизводят уже зарегистрированные ошибки; они не считаются новыми дефектами или дополнительными бизнес-тестами. Рабочая копия, ветка, индекс и исходные результаты build/test-results/test не изменяются скриптом.

## 3. DEF-01: полный формат UUID

Метод: RequestValidationApiTest.rejectsNonCanonicalUuid, четыре параметра.

В копии отключается условие FORMAT.matcher(value).matches() в ApiUuid. Остаётся стандартный UUID.fromString, принимающий сокращённую форму. Для 1-1-1-1-1 проверка требует 400, а без исправления получает 404. Скрипт проверяет именно этот вариант и пару HTTP-кодов в JUnit-свидетельстве. Остальные некорректные формы также проверяются, но их падения не подменяют свидетельство сокращённого UUID.

После восстановления файла те же четыре варианта должны проходить. Исправляющий коммит: 9bd3573. Исходные шаги, влияние и причины приведены в [DEF-01](defects.md#def-01-сокращённый-uuid-принимается-как-корректный).

## 4. DEF-02: календарные даты и отчёт

Методы SummaryReportBoundaryApiTest:

- preservesLargeDurationWithoutOverflowOrDecimalLoss: один отчёт для заявки с датами от 0001 до 9999 года.
- preservesCalendarDateInDatabaseAndReport: пять дат, включая годы 0001, 1500, границы октября 1582 и 9999.

В копии удаляется только настройка hibernate.type.preferred_instant_jdbc_type из application.yaml. Без исправления отчёт должен воспроизвести ошибку totalCreated=0 вместо 1. Скрипт требует соответствующее падение первого метода. Дополнительные варианты проверяют независимым чтением PostgreSQL сдвиг календарной даты при сохранении.

После восстановления конфигурации все шесть выполнений должны проходить. Исправляющий коммит: ba2deb0. Полная причина и ограничения исправления описаны в [DEF-02](defects.md#def-02-сдвиг-календарных-дат-при-передаче-instant-в-postgresql).

## 5. Артефакты и результаты

Каждый запуск сохраняет отдельный каталог build/regression-<id>:

- source.zip и project: снимок коммита и изолированная копия.
- DEF-01-without-fix, DEF-01-with-fix, DEF-02-without-fix, DEF-02-with-fix: журнал Gradle и JUnit XML каждого запуска.
- summary.json: полный SHA, UTC-время, код завершения, количество выполнений/падений/ошибок/пропусков и сообщения по каждому тесту.

Каталог не включается в Git. Скрипт печатает его путь, не удаляет результаты прежних запусков и завершает работу ошибкой, если ожидаемая регрессия не подтверждена. Команда clean удаляет каталог build вместе с этими свидетельствами.

Проверено 11.11.2026 в ветке feature-c/defect-regression, до коммита этапа. Снимок исходников: 0c0f2f309054adeb590c528f065810828b7cff2c. Окружение: Windows, PowerShell 7, Java 25, Kotlin 2.4.21, Docker, PostgreSQL 18.6. Команда: `.\scripts\verify-regressions.ps1`.

| DEF-01 | 4 выполнения, 4 падения, код Gradle 1 | 4 выполнения, 0 падений, код Gradle 0 | Для 1-1-1-1-1: ожидалось 400, получено 404 |
| DEF-02 | 6 выполнений, 4 падения, код Gradle 1 | 6 выполнений, 0 падений, код Gradle 0 | В отчёте ожидалось totalCreated=1, получено 0; три старые даты сдвинуты |

Во всех четырёх запусках XML-ошибок и пропусков нет. Скрипт завершился с кодом 0: ожидаемые проявления обоих дефектов найдены, все 10 выполнений с исправлениями успешны. Всего выполнено 20 проверок в двух состояниях кода; это не 20 уникальных тестов.

Контрольный каталог: build/regression-dd551f58. Главный файл summary.json и четыре набора JUnit XML находятся внутри него. Проверенные файлы основной рабочей копии совпадают с HEAD; в изолированной копии исправления восстановлены. Новых дефектов приложения не выявлено.
